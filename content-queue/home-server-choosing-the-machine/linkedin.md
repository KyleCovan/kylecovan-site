I am turning a 2019 iMac into an always on home server, and I am writing the whole build in public, including the parts where I was wrong.

Today I was wrong twice, and both are worth sharing.

**One.** Partway through deciding which machine to use, I found an entry in my own decision log, dated two weeks earlier, where I had already made the decision and written out the reasoning. I had done the work, documented it properly, and then forgotten I did it.

I arrived at nearly the same conclusion the second time, which tells me the reasoning was sound. It also tells me that writing something down is not the same as remembering it. A second brain only helps if you actually read it.

**Two.** That same entry said the iMac was a good choice partly because it was "still getting security updates." That was true when I wrote it in July. It is not true now. The machine is running Ventura, which has since fallen outside Apple's support window.

The conclusion survived. The machine is still the right machine. But it is only right after an upgrade, and until then it has the exact flaw I rejected another computer for.

That is the part I keep thinking about. A decision log is not a list of facts. It is a list of facts as of a date, and some of those facts expire faster than others. Anything about software support, pricing or availability has a short shelf life. I am going to start dating the assumptions inside my decisions, not just the decisions themselves.

The third thing I learned today could have cost real money, so I wrote it up separately: if you schedule an AI agent to run unattended, check which account it bills. A subscription and an API account are not the same thing, and nothing warns you when you cross between them.

Build log is on my site. More as I go.
